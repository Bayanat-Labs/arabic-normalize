      How it is computed
      
    
        
      
      1. A policy sets one mode for each of the 18 normalisation stages; the stages always run in the same order.
        2. 
      
      2. Character data comes from the Unicode 18.0.0 database bundled with the library, so the output does not change from one browser to another.
        3. 
      
      3. Every change is logged with its position in the original text, and the offset map links each output character to its position in the input.
        4. 
      
      4. Changes that can make two different words identical, such as ⁧ى⁩ to ⁧ي⁩, are flagged as lossy.
        5. 
      
      5. The SHA-256 identifies the policy exactly: cite the policy id and its hash, and anyone can reproduce the same output.
        6. 
    
      
    
      This page runs the JavaScript library @bayanat-labs/arabic-normalize, which gives the same output as the Python library arabic-normalize on every conformance case.
